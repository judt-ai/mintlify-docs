---
title: "File vs. Agent Edits"
---

Exploring two types of integration patterns.

Judt aims to make it dead simple for your agent to be able to ship fully functional web Apps. It does that by exposing strong primitives with simple editing & code writing. Brining flexibility and simplicity together.<br /><br />As part of this, you can decide how you want the integration to work: 

1. **Give your agent file editing capability:** Expose the raw files to your agent so it manages the full end-to-end lifecycle. This means your agent is in full control and can deploy, commit, write files, view previews and more. 
2. **Let the Judt agent (harness) manage it:** Instead of giving your agent access to the raw underlying tools, you can just send messages to our managed agent. Your agent sends a request of what it want and ours will go off an do that. Your agent can check-in on status to see what the Judt agent came back with. 

The obvious trade off here is where token spend is done. Judt will simply charge 20% extra on all token spend -- what ever our raw cost is. We aim over time to make it the best agent for building Judt based apps, so quality compound over time.
