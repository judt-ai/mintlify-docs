---
title: "File vs. Agent Edits"
description: "Choose between giving your agent the file tools and sending messages to the Judt agent."
---

Judt gives you two ways to integrate your agent:

1. **Give your agent file access.** Your agent controls the full lifecycle. It writes files, runs commands, views previews, commits, and deploys.
2. **Send messages to the Judt agent.** Your agent does not use the file tools. It tells the Judt agent what it wants, and the Judt agent does the work. Your agent can check the status and read the result.

The main difference is where the model tokens are used. With file access, your agent uses its own tokens. With the Judt agent, Judt runs the model. For costs, see [pricing](https://judt.ai/pricing).

## Advantages and disadvantages of the Judt agent

| Advantages | Disadvantages |
| --- | --- |
| **Simpler integration.** Your agent can use the Judt agent as a specialized sub-agent. You do not need to optimize your agent for Judt. | **Less control.** Your agent gets less detail. If it does not read the source code, it gets its context through summaries. |
| **Quality.** The Judt agent and its harness are made for this runtime and platform. | **Cost.** It can cost more, because the two agents use more messages to communicate and ask questions. |
