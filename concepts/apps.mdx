An App in JUDT is a top-level organizational unit — similar to a project or workspace. Each app has its own tools, agents, API keys, and usage metrics, keeping everything cleanly separated and independently configurable.

## What Is an App?

When you sign up, JUDT creates a default app for you so you can start building immediately. As your needs grow, you can create additional apps to separate environments (development, staging, production) or to represent entirely different products under your account. Each app is fully isolated: tools enabled in one app are not available in another, and API keys do not cross app boundaries.

## App Object

The following is an example of an app object returned by the JUDT API:

```json
{
  "id": "app_xyz789",
  "name": "My Product",
  "environment": "production",
  "created_at": "2024-01-10T08:00:00Z",
  "updated_at": "2024-01-18T11:45:00Z",
  "tools_enabled": ["web-search", "code-execution"],
  "agent_count": 3
}
```

The `tools_enabled` array lists every tool active for this app, and `agent_count` reflects how many agents are currently configured within it.

## Creating an App

Creating a new app takes only a few steps:

1. Open the JUDT **Dashboard** and navigate to **Apps** in the sidebar.
2. Click **New App**.
3. Give the app a name and select its environment (`development`, `staging`, or `production`).
4. Configure the tools you want to enable for the app.

Your new app is ready immediately with a fresh set of API keys and a clean usage slate.

## Environments

Use separate apps to represent each stage of your deployment pipeline. A `development` app lets you experiment with new tools and agent configurations without risk; a `staging` app mirrors production for pre-release testing; and your `production` app serves live traffic.

<Tip>
  Keep your production API keys out of local development by always pointing your local environment at a dedicated `development` app. This prevents accidental data writes or unexpected tool invocations against live resources.
</Tip>

## App API Keys

Each app has its own set of API keys, and those keys are scoped exclusively to that app. A key from your `production` app cannot be used to access your `staging` app, and vice versa. Rotate, revoke, and create keys independently for each app directly from the dashboard.

See the [Authentication](/authentication) page for details on how to include your API key in requests and how to manage key permissions.

## Usage & Billing

Every tool invocation and agent call made within an app is tracked against that app's quota. You can view invocation counts, latency breakdowns, and cost estimates per app from the **Usage** tab in the dashboard.

<Info>
  Usage and billing are tracked at the app level, not the account level. If you run multiple apps, review each app's usage tab individually to get an accurate picture of your costs.
</Info>
