Send a credential in the `Authorization` header of each request to the Judt REST API (`https://api.judt.ai/api`) and the Judt MCP server (`https://api.judt.ai/mcp`).

| Path | Who uses it | Access scope | How to start |
| --- | --- | --- | --- |
| **API key** _(primary)_ | Scripts, CI jobs, and agents | All Apps in one organization, or one App | Create a `judt_...` key on the [API keys](https://judt.ai/api-keys) page, or create a short-lived App token with `POST /api/tokens`. |
| **Agent OAuth** | Coding agents and MCP clients | All Apps in one organization (`apps:read`, `apps:write`) | Connect an OAuth client to the MCP server, or follow [`https://judt.ai/auth.md`](https://judt.ai/auth.md). |

## API keys (primary)

An API key is the primary credential for scripts, CI jobs, and agents. Each API key starts with `judt_`. Send the key as a bearer token:

```http
Authorization: Bearer judt_...
```

- **Create a key in the dashboard**: On the [API keys](https://judt.ai/api-keys) page, click **Create key**. Select **All apps** or select **one App**, and set an expiration time (`1 day` to `90 days`, or `No expiration`). Copy the key. The dashboard shows the full key one time only.
- **Create a short-lived App token with the API**: Use an organization-wide API key (`All apps`) to call `POST /api/tokens`. This endpoint creates a token for one App that expires after `60` to `86400` seconds (up to 24 hours). Give this token to an agent that must access only that App. See [Give an agent access to a single App](/manage/guides/agent-access).
- **Revoke a key**: Click **Revoke** next to the key on the [API keys](https://judt.ai/api-keys) page. The key stops working immediately.

## Agent OAuth

With OAuth, you approve an agent or MCP client in your browser. You do not copy a key. The access token acts as you in the organization that you select and uses the `apps:read` and `apps:write` scopes.

An agent can start OAuth in two ways:

- **From the MCP server**: Connect an MCP client that supports OAuth (such as Claude Code, Cursor, VS Code, claude.ai, or ChatGPT) to `https://api.judt.ai/mcp` without an `Authorization` header. The server returns `401 Unauthorized` with the `resource_metadata` URL in the `WWW-Authenticate` header, and the client opens your browser so you can sign in and approve access. See [Connect to MCP](/connect-to-mcp).
- **From `auth.md` and the OAuth endpoints**: Standalone agents follow the instructions at [`https://judt.ai/auth.md`](https://judt.ai/auth.md):
  1. Read the server metadata at `https://judt.ai/.well-known/oauth-authorization-server` (or `https://judt.ai/.well-known/poppy.json` for the Personal Agent Protocol).
  2. Register one time at `POST https://judt.ai/api/auth/oauth2/register`.
  3. Request a device code and user code at `POST https://judt.ai/api/auth/device/code`.
  4. Give the verification link (`https://judt.ai/device`) and the user code to the user.
  5. Poll `POST https://judt.ai/api/auth/oauth2/token` until the user approves access, and use the same endpoint to refresh tokens.

To disconnect an agent, go to [Connected agents](https://judt.ai/connected-agents) and click **Disconnect**. An agent can also revoke its own refresh token at `POST https://judt.ai/api/auth/oauth2/revoke`.

## Other details

- **Organization roles**: Every API key and OAuth token acts as you in one organization and has your role (`owner`, `admin`, or `member`). An agent cannot do an action that your role does not allow.
- **Tokens that open a private App**: To open a published App (`https://<slug>.judt.dev`) that uses `password` or `private` visibility without a browser sign-in, create a 5-minute access token with `POST /api/apps/{id}/access`. Send this token in the `X-Judt-Access-Token` header or the `access_token` URL parameter. See [Previews and access](/manage/concepts/previews).

For OAuth scopes, token lifetimes, DPoP key binding, role permissions, and error codes, see the [API reference](/api-reference/introduction).
