Set up your local environment to interact with JUDT securely by storing credentials in environment variables and using the JUDT SDK configuration options.

## Recommended Environment Variables

Store your JUDT credentials as environment variables rather than hardcoding them in your source code. At a minimum, set the following three variables:

```bash
JUDT_API_KEY=your_api_key_here
JUDT_APP_ID=your_app_id_here
JUDT_BASE_URL=https://api.judt.com/v1
```

<Warning>
  Never commit API keys or secrets to source control. Add `.env` to your `.gitignore` file and use a secrets manager (such as AWS Secrets Manager, HashiCorp Vault, or your CI provider's secret store) in production environments.
</Warning>

## Loading Variables in Code

Load your environment variables at application startup so every JUDT SDK call has access to them automatically.

<CodeGroup>

```javascript Node.js
// Install dotenv: npm install dotenv
import 'dotenv/config';

const apiKey = process.env.JUDT_API_KEY;
const appId = process.env.JUDT_APP_ID;
const baseUrl = process.env.JUDT_BASE_URL;

console.log('Connecting to JUDT at', baseUrl);
```

```python Python
# Install python-dotenv: pip install python-dotenv
from dotenv import load_dotenv
import os

load_dotenv()  # reads from .env in the current directory

api_key = os.environ['JUDT_API_KEY']
app_id  = os.environ['JUDT_APP_ID']
base_url = os.environ['JUDT_BASE_URL']

print(f"Connecting to JUDT at {base_url}")
```

```bash Shell
# Export variables directly in your shell session
export JUDT_API_KEY="your_api_key_here"
export JUDT_APP_ID="your_app_id_here"
export JUDT_BASE_URL="https://api.judt.com/v1"
```

</CodeGroup>

## Base URL Configuration

All JUDT API requests are made against the base URL:

```
https://api.judt.com/v1
```

If you are running tests against a sandbox environment, use the sandbox base URL instead:

```
https://sandbox.api.judt.com/v1
```

The sandbox environment is isolated from production data — API keys issued for production do **not** work against the sandbox, and vice versa. Set `JUDT_BASE_URL` to the appropriate value for each environment so you never accidentally hit production during development.

## Timeout and Retry Settings

Network conditions vary. Configure a sensible timeout and automatic retry strategy in your HTTP client to handle transient failures gracefully.

<CodeGroup>

```javascript Node.js
// Using axios with axios-retry
import axios from 'axios';
import axiosRetry from 'axios-retry';

const client = axios.create({
  baseURL: process.env.JUDT_BASE_URL,
  timeout: 30_000, // 30 seconds
  headers: {
    Authorization: `Bearer ${process.env.JUDT_API_KEY}`,
  },
});

axiosRetry(client, {
  retries: 3,
  retryDelay: axiosRetry.exponentialDelay, // 1s, 2s, 4s
  retryCondition: (error) =>
    axiosRetry.isNetworkOrIdempotentRequestError(error) ||
    error.response?.status === 429,
});
```

```python Python
# Using httpx with tenacity for retries
import httpx
import os
from tenacity import retry, stop_after_attempt, wait_exponential

http_client = httpx.Client(
    base_url=os.environ['JUDT_BASE_URL'],
    timeout=30.0,  # 30 seconds
    headers={"Authorization": f"Bearer {os.environ['JUDT_API_KEY']}"},
)

@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=1, max=8),
)
def call_judt(path: str, payload: dict):
    response = http_client.post(path, json=payload)
    response.raise_for_status()
    return response.json()
```

</CodeGroup>

## SDK Quick Config

The JUDT Python SDK accepts all critical options at initialization. Pass your credentials and timeout once, and every subsequent call inherits them automatically.

```python
import judt
import os

client = judt.Client(
    api_key=os.environ['JUDT_API_KEY'],
    app_id=os.environ['JUDT_APP_ID'],
    timeout=30.0
)

# All calls made through `client` use the settings above
result = client.tools.invoke("web-search", {"query": "JUDT documentation"})
print(result)
```

<Note>
  Check the [JUDT SDK changelog](/changelog) before upgrading to a new SDK version — breaking changes, new configuration options, and deprecation notices are all listed there. Pin your SDK version in `requirements.txt` or `package.json` and test upgrades in a non-production environment first.
</Note>
