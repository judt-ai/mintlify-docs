This guide covers how to manage your JUDT apps from the dashboard — creating apps, managing API keys, setting up separate environments, and reviewing usage.

## Creating a New App

Each app in JUDT is an isolated container for your API keys, tool configurations, and agent definitions. Create a separate app for each project or environment.

<Steps>
  <Step title="Open the Apps screen">
    In your dashboard, navigate to **Apps → New App**.
  </Step>

  <Step title="Name your app and select an environment">
    Enter a descriptive name (for example, `my-product-production`) and choose an environment from the dropdown: **development**, **staging**, or **production**. The environment label is for your reference — it does not affect API behaviour, but it helps you organise keys and set appropriate usage alerts later.
  </Step>

  <Step title="Create the app">
    Click **Create App**. Your new app is ready immediately and comes with one default API key. Copy the key now — it will not be shown in full again.
  </Step>
</Steps>

## Managing API Keys

Every app can have multiple named API keys. Use separate keys for different services or team members so you can revoke access granularly without disrupting other integrations.

**To create a new key:**
1. Open the app in **Dashboard → Apps**.
2. Select the **API Keys** tab.
3. Click **New Key**, give it a descriptive name (for example, `backend-service` or `ci-pipeline`), and click **Generate**.
4. Copy the key immediately — JUDT only displays the full value once.

**To revoke a key:**
1. Find the key in the **API Keys** tab.
2. Click **Revoke** next to the key name.
3. Confirm the action. Revocation is immediate — any requests using that key will return `401 Unauthorized`.

<Warning>
  Rotate your API keys regularly. A compromised key gives full API access under your account. If you suspect a key has been exposed, revoke it immediately and generate a replacement. Store keys in environment variables or a secrets manager — never commit them to source control.
</Warning>

## Environment Strategy

Run parallel apps for each stage of your development lifecycle. This prevents test traffic from polluting production metrics and lets you validate configuration changes before they go live.

| Environment | Purpose | Recommended Key Rotation |
|---|---|---|
| development | Local testing and feature development | On demand |
| staging | Pre-release validation and QA | Monthly |
| production | Live user traffic | Quarterly |

Promote configuration changes through the pipeline: develop and test locally, validate on staging, then replicate the same tool configs and agent settings to your production app.

## Monitoring Usage

Open **Dashboard → Metrics** to review real-time and historical usage data for your app. The metrics view breaks down activity by:

- **Invocation count** — total tool and agent calls over a selected time range
- **Latency** — p50, p95, and p99 response times per tool and agent
- **Error rate** — the percentage of calls that returned an error, grouped by error code

Use the filter controls to drill down by tool, agent, or time period. Export raw data as CSV for offline analysis or billing reconciliation.

<Tip>
  Set usage alerts under **Dashboard → Metrics → Alerts** to receive an email or webhook notification when your invocation count or error rate crosses a threshold. This helps you catch runaway loops or unexpected traffic spikes before they affect your bill or your users.
</Tip>

## Deleting an App

<Warning>
  Deleting an app is **irreversible**. All API keys, tool configurations, agent definitions, and usage history associated with the app are permanently removed. Make sure you have migrated any active integrations to another app before proceeding.
</Warning>

To delete an app:

1. Navigate to **Dashboard → Apps** and open the app you want to remove.
2. Go to the **Settings** tab.
3. Scroll to the **Danger Zone** section and click **Delete App**.
4. Type the app name to confirm, then click **Permanently Delete**.

The app and all its resources are removed immediately.
