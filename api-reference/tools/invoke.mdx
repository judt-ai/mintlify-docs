---
title: 'POST /v1/tools/invoke — Execute a JUDT Tool at Runtime'
sidebarTitle: 'Invoke Tool'
description: 'Execute any enabled JUDT tool by ID with a structured input payload. Returns the tool result, latency stats, and full request metadata.'
---

This endpoint is the primary way to execute a tool at runtime. You send a tool ID, a structured input payload, and the app context — JUDT runs the tool, captures its output, and returns the result along with latency and usage data. The tool must be enabled for your app before you can invoke it.

**Endpoint:** `POST https://api.judt.com/v1/tools/invoke`

**Required scope:** `invoke`

---

## Request Body

<ParamField body="tool_id" type="string" required>
  The unique identifier of the tool you want to invoke. You can retrieve available tool IDs from the [List Tools](/api-reference/tools/list) endpoint.
</ParamField>

<ParamField body="input" type="object" required>
  The tool-specific input payload. The shape of this object depends on the tool being invoked. Refer to the tool's schema in your JUDT dashboard for the full list of accepted fields.

  <Expandable title="Example fields for web-search">
    <ParamField body="input.query" type="string" required>
      The search query string to execute.
    </ParamField>

    <ParamField body="input.max_results" type="integer">
      The maximum number of results to return. Overrides the value set in the tool's app-level configuration for this invocation only.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="app_id" type="string" required>
  The ID of the app this invocation belongs to. JUDT uses this to apply the correct tool configuration and enforce app-level permissions.
</ParamField>

<ParamField body="context" type="object">
  Optional key-value metadata to pass through to the tool. Use this to carry request-scoped information such as `user_id`, `session_id`, or custom trace identifiers. Context values are logged with the invocation record but are not passed to external APIs unless the tool explicitly uses them.
</ParamField>

<ParamField body="timeout_ms" type="integer" default="30000">
  Override the default execution timeout for this invocation, in milliseconds. The maximum allowed value is `120000` (120 seconds). If the tool does not complete within this window, JUDT returns a `tool_timeout` error.
</ParamField>

## Request Example

<CodeGroup>

```bash cURL
curl -X POST https://api.judt.com/v1/tools/invoke \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "tool_id": "web-search",
    "app_id": "app_xyz789",
    "input": {
      "query": "latest developments in large language models",
      "max_results": 5
    },
    "context": {
      "user_id": "usr_123",
      "session_id": "sess_abc"
    },
    "timeout_ms": 15000
  }'
```

```python Python
import requests

response = requests.post(
    "https://api.judt.com/v1/tools/invoke",
    headers={
        "Authorization": "Bearer YOUR_API_KEY",
        "Content-Type": "application/json",
    },
    json={
        "tool_id": "web-search",
        "app_id": "app_xyz789",
        "input": {
            "query": "latest developments in large language models",
            "max_results": 5,
        },
        "context": {
            "user_id": "usr_123",
            "session_id": "sess_abc",
        },
        "timeout_ms": 15000,
    },
)

data = response.json()
print(data["data"]["result"])
```

</CodeGroup>

## Response

A successful invocation returns a `200 OK` with the following structure:

```json
{
  "success": true,
  "data": {
    "tool_id": "web-search",
    "result": {
      "results": [
        {"title": "...", "url": "...", "snippet": "..."}
      ]
    },
    "usage": {
      "latency_ms": 420,
      "tokens_used": null
    }
  },
  "meta": {
    "request_id": "req_xyz456",
    "timestamp": "2024-01-15T10:05:00Z"
  }
}
```

<ResponseField name="success" type="boolean">
  `true` when the tool executed without errors.
</ResponseField>

<ResponseField name="data" type="object">
  The invocation result object.

  <Expandable title="Data fields">
    <ResponseField name="data.tool_id" type="string">
      The ID of the tool that was invoked, echoed back for confirmation.
    </ResponseField>

    <ResponseField name="data.result" type="object">
      The structured output produced by the tool. The shape of this object is tool-specific. Refer to the tool's schema in your dashboard for the full output specification.
    </ResponseField>

    <ResponseField name="data.usage" type="object">
      Resource usage statistics for this invocation.

      <Expandable title="Usage fields">
        <ResponseField name="data.usage.latency_ms" type="integer">
          End-to-end execution time for the tool, in milliseconds.
        </ResponseField>

        <ResponseField name="data.usage.tokens_used" type="integer | null">
          Number of tokens consumed, for tools that use language model calls. `null` for tools that do not consume tokens.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="meta" type="object">
  Request metadata.

  <Expandable title="Meta fields">
    <ResponseField name="meta.request_id" type="string">
      A unique identifier for this invocation. Include this when contacting support.
    </ResponseField>

    <ResponseField name="meta.timestamp" type="string">
      ISO 8601 timestamp indicating when JUDT received and processed the request.
    </ResponseField>
  </Expandable>
</ResponseField>

## Error Responses

| Error code | HTTP status | Description |
|---|---|---|
| `tool_not_found` | `404` | No tool exists with the given `tool_id`. Verify the ID using the [List Tools](/api-reference/tools/list) endpoint. |
| `tool_disabled` | `403` | The tool exists but is not enabled for the specified `app_id`. [Configure the tool](/api-reference/tools/configure) before invoking it. |
| `invalid_input` | `400` | The `input` object is missing required fields or contains values that fail the tool's schema validation. |
| `tool_timeout` | `504` | The tool did not complete within the `timeout_ms` window. Retry with a longer timeout or reduce input complexity. |
| `insufficient_scope` | `403` | The API key used does not have the `invoke` scope. Generate a new key with the correct permissions in your dashboard. |
