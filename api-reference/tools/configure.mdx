Use this endpoint to enable a tool for your app and set its configuration parameters before invoking it. Each tool has a set of configuration options — such as result limits, language preferences, or safety settings — that govern its behavior whenever it runs under your app. You must enable a tool through this endpoint before you can call it via [Invoke Tool](/api-reference/tools/invoke).

**Endpoint:** `POST https://api.judt.com/v1/tools/configure`

**Required scope:** `write`

---

## Request Body

<ParamField body="app_id" type="string" required>
  The ID of the app you are configuring the tool for. Tool configurations are scoped per app — the same tool can have different settings across different apps.
</ParamField>

<ParamField body="tool_id" type="string" required>
  The unique identifier of the tool to configure. Retrieve available tool IDs from the [List Tools](/api-reference/tools/list) endpoint.
</ParamField>

<ParamField body="enabled" type="boolean" required>
  Set to `true` to enable the tool for the app, or `false` to disable it. Disabling a tool prevents it from being invoked but does not delete its configuration — see [Disabling a Tool](#disabling-a-tool) below.
</ParamField>

<ParamField body="config" type="object">
  Tool-specific configuration parameters. The available fields depend on the tool. If omitted, JUDT applies the tool's platform defaults.

  <Expandable title="Example fields for web-search">
    <ParamField body="config.max_results" type="integer">
      The maximum number of search results to return per invocation. Can be overridden at invocation time using the `input.max_results` field.
    </ParamField>

    <ParamField body="config.safe_search" type="boolean">
      When `true`, enables safe search filtering to exclude explicit content from results. Defaults to `true`.
    </ParamField>

    <ParamField body="config.language" type="string">
      An ISO 639-1 language code (e.g. `en`, `fr`, `de`) that biases search results toward a specific language. Defaults to `en`.
    </ParamField>
  </Expandable>
</ParamField>

---

## Request Example

The following request enables the `web-search` tool for app `app_xyz789` and sets a custom configuration:

```bash
curl -X POST https://api.judt.com/v1/tools/configure \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "app_id": "app_xyz789",
    "tool_id": "web-search",
    "enabled": true,
    "config": {
      "max_results": 5,
      "safe_search": true,
      "language": "en"
    }
  }'
```

---

## Response

A successful request returns a `200 OK` confirming the updated configuration:

```json
{
  "success": true,
  "data": {
    "app_id": "app_xyz789",
    "tool_id": "web-search",
    "enabled": true,
    "config": {
      "max_results": 5,
      "safe_search": true
    },
    "updated_at": "2024-01-15T10:10:00Z"
  }
}
```

<ResponseField name="success" type="boolean">
  `true` when the configuration was saved without errors.
</ResponseField>

<ResponseField name="data" type="object">
  The saved configuration record.

  <Expandable title="Data fields">
    <ResponseField name="data.app_id" type="string">
      The app the configuration applies to.
    </ResponseField>

    <ResponseField name="data.tool_id" type="string">
      The tool that was configured.
    </ResponseField>

    <ResponseField name="data.enabled" type="boolean">
      The current enabled state of the tool for this app.
    </ResponseField>

    <ResponseField name="data.config" type="object">
      The full configuration that is now active for this tool under this app.
    </ResponseField>

    <ResponseField name="data.updated_at" type="string">
      ISO 8601 timestamp of when the configuration was last updated.
    </ResponseField>
  </Expandable>
</ResponseField>

## Disabling a Tool

To disable a tool without removing its configuration, send the same request with `"enabled": false`. All other `config` fields are preserved and will be restored the next time you re-enable the tool.

```bash
curl -X POST https://api.judt.com/v1/tools/configure \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "app_id": "app_xyz789",
    "tool_id": "web-search",
    "enabled": false
  }'
```

Any invocation attempt against a disabled tool returns a `tool_disabled` (`403`) error. Re-enable the tool at any time by sending `"enabled": true`.

---

<Note>
  Configuration changes take effect immediately — all invocations that start after a successful configure response will use the updated settings. In-flight invocations that began before the change are not affected.
</Note>
